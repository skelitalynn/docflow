# 协作文档系统需求文档（MVP优先版）

## 0. 文档信息

- 文档版本：v2.0（MVP优先）
- 目标读者：产品 / 研发 / 测试
- 优先级定义
  - **P0（必做）**：本次必须完成，保证可演示闭环与可验收
  - **P1（增强）**：时间允许则做，提升体验/加分
  - **P2（选做/加分）**：高成本或高风险功能，后续迭代

------

## 1. 背景与目标

### 1.1 背景

团队需要一个支持多人在线协作的文档系统，用于创建、共享、评论与协作讨论，并具备清晰的权限控制与通知闭环。

### 1.2 本期目标（只承诺 P0）

在 P0 范围内实现：

1. **账号体系闭环**：注册/登录/找回/重置
2. **文档闭环**：创建-编辑-自动保存-分享权限-删除（软删可选）
3. **协作感闭环（弱实时）**：在线成员展示（presence）+ 保存冲突提示（不做 OT/CRDT 合并）
4. **评论闭环**：评论/回复/@提及
5. **通知闭环**：站内通知（含未读/已读）
6. **审计闭环**：关键操作日志可追溯

------

## 2. 业务范围与里程碑

### 2.1 系统内（P0 必做）

- 用户管理：注册/登录/找回重置、基础资料
- 权限管理：系统角色 + 文档 ACL
- 文档管理：创建/查看/编辑/重命名/删除、模板库、自动保存与恢复、分类（文件夹+标签）、全文/高级搜索与排序
- 协作（弱实时）：presence、冲突检测（基于版本号）
- 评论：块级/段落级评论、回复、@提及
- 通知：站内通知（列表、未读数、已读）

### 2.2 系统内（P1 增强）

- 光标/选区同步（presence 的增强）
- 断线重连状态恢复体验优化
- 回收站（软删除恢复）、收藏/置顶
- 通知设置（按类型订阅/免打扰）

### 2.3 系统内（P2 选做/加分，明确不承诺）

- OT/CRDT 真协同合并
- 版本历史/对比/回滚/锁定
- 多格式导入导出（Word/PDF/Markdown）
- 聊天、视频会议、屏幕共享、文件共享
- 移动端离线编辑与同步
- 系统监控报警、健康报告、灰度开关

### 2.4 里程碑建议（用于排期与验收）

- **M1（地基）**：用户/权限模型 + 文档表结构 + ACL 校验中间件
- **M2（单人闭环）**：文档 CRUD + 模板库 + 自动保存 + 分类（文件夹+标签）+ 搜索（全文/高级）
- **M3（多人闭环）**：WebSocket presence + 评论/@ + 站内通知
- **M4（防事故）**：保存冲突检测（version 乐观锁）+ 关键审计日志 + 演示脚本

## 3. 术语与定义

- **系统角色**：Admin（管理员）/ User（普通用户）
- **文档 ACL**（文档级权限）：Owner / Editor / Viewer
- **用户权限角色**：管理员=系统角色 Admin；编辑者/查看者=文档 ACL 的 Editor/Viewer（Owner 为文档所有者）
- **presence**：在线协作者状态（谁在看/编辑）
- **文档版本号 version**：用于保存时冲突检测（乐观锁），不是“版本控制功能”

------

## 4. 用户与权限模型（必须写死，防歧义）

### 4.1 系统角色

- **Admin**：系统级管理权限（可查看/修复；是否越权访问文档由项目决定，P0 默认：仅用于后台管理与排障，不自动拥有所有文档内容编辑权）
- **User**：普通用户，文档访问由 ACL 决定

### 4.2 文档 ACL 权限

- **Owner**：管理 ACL、编辑、删除、查看审计日志（本文件范围）
- **Editor**：编辑、评论、@提及
- **Viewer**：查看、评论（P0 默认允许评论；是否可配置放到 P1）

### 4.3 硬规则（P0）

1. **只有 Owner / Admin 可以修改 ACL**
2. 文档列表与搜索结果必须进行 **ACL 过滤**
3. 服务端强校验权限，前端仅展示

------

## 5. 功能需求（P0）

### 5.1 用户管理模块（P0）

#### 5.1.1 注册与登录

- 支持邮箱/手机号注册
- 密码登录
- 找回密码与重置密码（验证码/邮件链接任选一种实现）

**验收**

- 新用户可完成注册→登录→找回→重置完整链路

#### 5.1.2 用户信息

- 个人资料编辑：昵称（P0）
- 头像上传与设置（P1，可选）
- 联系信息管理：邮箱/手机号绑定与变更（P1，可选）

#### 5.1.3 用户权限管理

- 角色定义：系统角色 Admin/User；文档角色 Owner/Editor/Viewer（对应管理员/编辑者/查看者）
- 权限分配：Owner/Admin 管理文档 ACL（分享/撤销/变更）
- ACL 强校验：列表/搜索/详情均需过滤
- 操作日志：记录注册/登录、密码重置、ACL 变更等关键动作

------

### 5.2 文档管理模块（P0）

#### 5.2.1 文档创建与编辑

- 创建文档：标题 + 内容（可选模板）
- 编辑文档：支持富文本/Markdown/纯文本（以可稳定存取为准）
- 模板库：支持创建/复用模板
- 重命名文档
- 删除文档：P0 建议软删除（`deleted_at`），没时间可先硬删但需审计

#### 5.2.2 自动保存与恢复（P0）

- 自动保存：客户端每 N 秒调用保存接口（N 默认 10s）
- 恢复：重新打开文档显示最近一次保存内容
- 失败提示：保存失败提示可重试（网络/权限/冲突）

#### 5.2.3 分类与列表（P0）

- 文件夹 + 标签：同时支持文件夹与标签分类
- 文档列表：只展示有权限文档，支持分页、按更新时间排序

#### 5.2.4 搜索（P0）

- 标题/内容关键字匹配（数据库 LIKE 或基础索引方案）
- 高级搜索：作者/日期/关键词组合筛选
- 必须做 ACL 过滤
- 支持排序（默认按更新时间）+ 分页

------

### 5.3 协作模块（P0：弱实时，不做 OT/CRDT）

#### 5.3.1 presence（P0）

- 同一文档打开时显示在线协作者列表（进入/离开）
- presence 通过 WebSocket 推送

#### 5.3.2 保存冲突检测（P0 核心）

- 文档表包含 `version`（int）
- 客户端保存时带上 `base_version`
- 服务端更新规则：仅当 `base_version == current_version` 才允许更新并 `version+1`
- 若版本不一致返回 **409 冲突**，客户端提示：
  - “文档已被他人更新，请刷新后再编辑”
  - （P1）可生成“本地副本/草稿”避免丢失

**验收**

- 两人同时编辑：后保存者不会悄悄覆盖，必然收到冲突提示

------

### 5.4 评论与@模块（P0）

#### 5.4.1 评论形态（P0 简化）

- **块级/段落级锚点**（避免字符级锚点漂移难题）
- 评论线程：评论 + 回复
- 状态：开放/已解决（可选 P1）

#### 5.4.2 @提及（P0）

- 在评论中 `@用户名` 或从用户列表选择
- 被@的人收到站内通知

------

### 5.5 通知模块（P0：站内通知）

#### 5.5.1 通知类型（P0）

- 被分享文档 / 权限变更
- 评论被回复
- 被@提及

#### 5.5.2 通知中心（P0）

- 通知列表、未读数
- 标记已读/全部已读
- 点击跳转到对应文档/评论上下文（能定位到评论所在块）

------

### 5.6 审计与日志（P0）

记录以下关键动作：

- 注册、登录成功/失败、密码重置
- 文档创建/编辑/删除/重命名
- ACL 变更（授权/撤销/变更权限）
- 评论创建、@提及（可选）

------

## 6. 业务规则与异常处理（P0）

### 6.1 权限异常

- 无权限：返回 403，并在前端提示“无访问权限”
- ACL 变更即时生效：已打开文档的用户若被降权/移除：
  - P0 最低要求：下一次保存/操作时返回 403/409 并提示
  - P1：实时踢出或切只读

### 6.2 保存冲突

- 冲突返回 409，必须给出当前版本号与更新时间，前端可提示刷新

### 6.3 WebSocket 断线

- P0：断线后 presence 可能延迟消失（可通过心跳超时 T=30s 清理）
- P1：断线重连自动恢复 presence

------

## 7. 非功能需求（P0 可测版本）

### 7.1 性能（在“课程项目规模假设”下）

- 文档列表（1000 条以内）：P95 < 800ms
- 文档打开：P95 < 1.5s
- 搜索（LIKE 级别）：P95 < 1.5s
- presence 推送：P95 < 500ms（同地域）

### 7.2 安全

- 密码强哈希存储（bcrypt/argon2）
- HTTPS（开发环境可放宽）
- 上传（若做头像/图片）：限制类型与大小；防止 XSS（富文本需清洗）

### 7.3 可用性与容错

- WebSocket 挂了不影响文档 CRUD（只影响协作感）
- 保存失败可重试，前端明确提示

## 8. 数据与对象模型（概念级，P0）

### 8.1 核心实体

- **User**：id、email/phone、password_hash、system_role、nickname、avatar_url、status、created_at、updated_at
- **Document**：id、title、content、owner_id、folder_id、version、created_at、updated_at、deleted_at（可选）
- **DocMember（ACL）**：doc_id、user_id、acl_role（Owner/Editor/Viewer）、created_at、created_by
- **Folder（若做文件夹）**：id、user_id、name、parent_id
- **Comment**：id、doc_id、anchor（block_id/paragraph_index）、thread_id、author_id、content、created_at
- **Notification**：id、user_id、type、payload、is_read、created_at
- **AuditLog**：id、actor_id、action、target_type、target_id、result、ip、created_at

## 9. 接口与事件（概要，P0）

### 9.1 REST API（示例）

- Auth：`POST /auth/register` `POST /auth/login` `POST /auth/forgot` `POST /auth/reset`
- User：`GET /users/me` `PUT /users/me`
- Document：`POST /docs` `GET /docs/:id` `PUT /docs/:id`（带 base_version）`DELETE /docs/:id`
- ACL：`GET /docs/:id/members` `PUT /docs/:id/members`（仅 Owner/Admin）
- Folder/Search：`GET /docs?folder=...` `GET /search?q=...`
- Comment：`POST /docs/:id/comments` `POST /comments/:id/replies`
- Notification：`GET /notifications` `POST /notifications/read`

### 9.2 WebSocket 事件（P0）

- `presence.join` / `presence.leave`
- `notification.push`（站内通知推送）

## 11. 验收与演示脚本（建议）

1. A 注册登录 → 创建文档 → 分享给 B 为 Viewer

## UC-01 注册

**参与者**：访客
**触发**：访客点击“注册”

### 前置

- 访客未登录
- 系统可用，注册入口可访问

### 主流程

1. 访客输入邮箱/手机号、密码、验证码（如有）。
2. 系统校验账号格式、密码规则、验证码有效性。
3. 系统检查账号是否已存在。
4. 系统创建用户账户，生成默认资料（昵称可为空/默认值）。
5. 系统返回注册成功（可同时返回登录态 token / session）。

### 异常

- A1 账号已存在：提示“账号已注册”，引导登录/找回密码。
- A2 验证码错误/过期：提示重新获取验证码。
- A3 密码不符合规则：提示规则并阻止提交。
- A4 系统异常/DB失败：提示稍后再试，不创建账户。

### 后置

- 用户账户存在（状态=正常）
- （若自动登录）产生有效登录态

------

## UC-02 登录

**参与者**：用户
**触发**：用户输入账号密码点击“登录”

### 前置

- 用户已注册
- 用户未处于封禁/冻结状态

### 主流程

1. 用户输入账号（邮箱/手机号）和密码。
2. 系统校验账号存在性与密码正确性。
3. 系统生成登录态（token/session），返回用户信息与角色。
4. 进入系统首页/文档列表。

### 异常

- A1 账号不存在：提示“账号不存在”，引导注册。
- A2 密码错误：提示错误；累计失败次数（可选限流）。
- A3 账号冻结/封禁：提示不可登录并给出原因/联系管理员。
- A4 系统异常：提示稍后再试。

### 后置

- 登录态有效
- 记录审计日志：登录成功/失败（含IP、时间、结果）

------

## UC-03 找回密码

**参与者**：访客/用户
**触发**：点击“忘记密码”

### 前置

- 账号存在且允许找回
- 系统配置了找回方式（邮箱链接或短信验证码，P0任选其一）

### 主流程（以“验证码”举例）

1. 输入账号（邮箱/手机号）。
2. 系统校验账号存在。
3. 系统发送验证码（短信/邮件）。
4. 用户输入验证码提交。
5. 系统验证通过，允许进入“重置密码”页面（发放一次性重置凭证/短期token）。

### 异常

- A1 账号不存在：提示“账号不存在”。
- A2 发送频率过高：提示稍后再试（限流）。
- A3 验证码错误/过期：提示重新获取。
- A4 系统异常：提示稍后再试。

### 后置

- 用户获得一次性重置权限（短期有效）
- 记录审计日志：发起找回密码

------

## UC-04 重置密码

**参与者**：用户
**触发**：在找回流程中点击“确认重置”

### 前置

- 已通过 UC-03 验证（持有有效重置凭证）
- 账号正常

### 主流程

1. 用户输入新密码与确认密码。
2. 系统校验密码规则与两次一致。
3. 系统更新密码哈希，作废旧登录态（建议作废所有token/session）。
4. 返回“重置成功”，引导重新登录（或自动登录）。

### 异常

- A1 凭证无效/过期：提示重新发起找回。

## UC-08 编辑文档（手动保存）

**参与者**：Editor / Owner
**触发**：用户编辑后点击“保存”（或编辑器触发保存）

### 前置

- 用户已登录
- 对文档具备 Editor+ 权限
- 客户端持有 `base_version`

### 主流程

1. 用户修改内容。
2. 客户端发送保存请求：doc_id、content、base_version。
3. 系统校验权限（Editor+）。
4. 系统校验版本：base_version == current_version。
5. 校验通过：保存内容，version+1，更新 updated_at。
6. 返回保存成功与 new_version。

### 异常

- A1 权限不足：403。
- A2 版本冲突：409（转 UC-16 冲突处理）。
- A3 内容非法/超限：400，提示。
- A4 系统异常：500，提示稍后再试。

### 后置

- 文档内容更新，version递增
- 记录审计日志：编辑保存（含是否成功）

## UC-09 自动保存

**参与者**：Editor / Owner
**触发**：编辑器每 N 秒触发

### 前置

- 同 UC-08
- 客户端有定时器/防抖策略，避免频繁请求

### 主流程

1. 客户端检测内容有变化且距离上次保存超过 N 秒。
2. 发起保存请求（同 UC-08）。
3. 保存成功后更新本地 base_version。

### 异常

- A1 冲突 409：停止自动保存，提示用户处理冲突（进入 UC-16）。
- A2 网络失败：提示“离线/保存失败”，允许重试。
- A3 权限变更导致403：提示“权限已变更，无法保存”。

### 后置

- 成功则文档持久化并更新 version
- 失败则保留本地内容，等待用户处理

## UC-15 加入协作会话（presence.join/leave）

**参与者**：Viewer+
**触发**：打开文档时建立 WebSocket 连接

### 前置

- 用户已登录
- 对文档具备 Viewer+ 权限
- WebSocket 服务可用（不可用时允许降级：不显示presence）

### 主流程

1. 客户端建立 WS 连接并发送 join(doc_id, user_id)。
2. 服务端校验权限（Viewer+）。
3. 服务端将用户加入该 doc 的在线成员集合。
4. 服务端广播 presence 更新给该 doc 的其他在线用户。
5. 客户端展示在线协作者列表。

### 异常

- A1 WS 连接失败：降级为无presence模式（不影响CRUD）。
- A2 权限不足：服务端拒绝join并断开/返回错误。
- A3 心跳超时：服务端将用户移出在线集合并广播 leave。

### 后置

- 在线成员集合更新
- 可能触发审计日志（可选）

## UC-16 保存冲突处理（409）

**参与者**：Editor+
**触发**：保存返回 409

### 前置

- 用户处于编辑状态，保存时 base_version 落后
- 服务端返回：current_version、updated_at（建议）及可选 diff 信息（P0可不做）

### 主流程（P0最小可验收）

1. 客户端收到 409 冲突响应。
2. 客户端提示：“文档已被他人更新，请刷新后再编辑”。
3. 用户选择：
   - 方案A：刷新重新加载最新内容（丢弃本地改动，或先复制到剪贴板）
   - 方案B（P1）：保存为“本地副本/草稿”再手动合并

### 异常

- A1 用户持续保存：仍返回409，直到刷新或拿到新 base_version。
- A2 刷新后仍无法保存：可能权限被降级（403）或文档被删除（404）。

### 后置

- P0：保证“不发生静默覆盖”
- 记录审计日志：冲突发生（可选但很建议）
