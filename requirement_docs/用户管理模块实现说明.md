# 用户管理模块实现说明

本文档说明当前项目中“用户管理模块”的实现内容、接口和测试要点，用于对照需求清单验收。

## 1. 角色与权限模型

- 系统角色（SystemRole）：ADMIN / USER
  - ADMIN 负责系统级管理操作（例如调整系统角色）
  - USER 为普通用户
- 文档权限（DocRole）：OWNER / EDITOR / VIEWER
  - OWNER/EDITOR/VIEWER 对应“管理员/编辑者/查看者”的文档权限
  - ACL 权限由 Owner/Admin 管理，服务端强校验

## 2. 功能覆盖对照

### 2.1 用户注册与登录

- 邮箱/手机号注册：已实现
  - 支持 email / phone 二选一或同时填写
- 密码登录：已实现
- 找回与重置：已实现
  - /auth/forgot 返回 resetToken（可视为验证码）
  - /auth/reset 使用 resetToken + newPassword 完成重置
  - token 有效期 30 分钟，且单次使用

### 2.2 用户信息管理

- 个人资料编辑：已实现（昵称）
- 头像上传与设置：已实现（multipart 上传）
- 联系信息管理：已实现（邮箱/手机号绑定与变更）

### 2.3 用户权限管理

- 角色定义：已实现（SystemRole + DocRole）
- 权限分配：已实现（ACL 管理接口、管理员角色调整）
- 访问控制列表（ACL）：已实现（文档成员表 + 强校验）
- 操作日志记录：已实现（注册/登录/重置/ACL 变更等）

## 3. 主要接口（P0 相关）

### 3.1 Auth

- `POST /auth/register`
- `POST /auth/login`
- `POST /auth/forgot`
- `POST /auth/reset`

### 3.2 User

- `GET /users/me`
- `PUT /users/me`
- `POST /users/me/avatar`（multipart 表单上传）
- `GET /users/me/audit`（查看本人操作日志）

### 3.3 ACL（文档权限）

- `GET /docs/{id}/members`
- `PUT /docs/{id}/members`（Owner/Admin 才可修改）

### 3.4 Admin

- `PUT /admin/users/{id}/role`（仅 ADMIN）
- `GET /admin/users/{id}/audit`（仅 ADMIN）

## 4. 关键数据表

- `t_user`：用户基础信息（email/phone/nickname/avatar_url/system_role/status）
- `t_password_reset`：找回密码 token 记录
- `t_doc_member`：文档 ACL
- `t_audit_log`：操作日志

## 5. 管理员初始化（可选）

如需快速创建管理员，可在 `application.properties` 中配置：

```
docflow.bootstrap.enabled=true
docflow.bootstrap.admin-email=admin@example.com
docflow.bootstrap.admin-phone=
docflow.bootstrap.admin-password=admin123
docflow.bootstrap.admin-nickname=admin
```

启动后若系统中不存在 ADMIN，将自动创建或提升指定用户为 ADMIN。

## 6. 验收/演示流程建议

1. 注册账号（邮箱或手机号），登录获取 token
2. 忘记密码 → 获取 resetToken → 重置密码 → 用新密码登录
3. 修改资料（昵称/邮箱/手机号）
4. 上传头像并通过 `/avatars/...` 访问
5. 创建文档并通过 ACL 分配 Editor/Viewer
6. 查看用户操作日志与文档审计日志

以上流程覆盖用户管理模块的主要验收点。
