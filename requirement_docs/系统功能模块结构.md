## 1. 系统功能模块结构

### 1.1 功能模块总览（P0）

按业务域拆分为 9 个核心模块 + 1 个横切模块：

1) **用户与鉴权模块（Auth/User）**
- 注册、登录、找回/重置密码
- Token/Session 管理
- 用户资料（昵称/头像/联系方式）
- 账号绑定/变更（邮箱/手机号，P1 可选）

2) **文档模块（Document）**
- 文档创建/查看/编辑保存/重命名/删除（软删优先）
- 富文本/Markdown/纯文本编辑（content_format 标识）
- 模板库（创建/复用模板）
- 自动保存与恢复（客户端定时保存，重新打开取最近一次保存）
- 文档列表与分类（文件夹 + 标签）
- 全文搜索 + 高级搜索（作者/日期/关键词）+ 排序

3) **权限模块（ACL/DocMember）**
- 文档 ACL：Owner/Editor/Viewer
- 分享/撤销/权限变更
- **Owner 唯一性约束**：至少存在 1 个 Owner（禁止移除/降级最后一个 Owner）fileciteturn3file0

4) **协作模块（Collaboration，弱实时）**
- WebSocket 连接与鉴权
- presence：加入/离开、在线成员列表广播
- 保存冲突检测：version 乐观锁（409，不静默覆盖）fileciteturn3file0

5) **评论与提及模块（Comment/Mention）**
- 块/段落级锚点评论（避免字符级漂移）
- 回复线程
- @提及记录与通知触发

6) **任务模块（Task）**
- 任务创建与分配
- 任务状态跟踪（待办/进行中/已完成）
- 截止日期设置
- 任务完成通知

7) **通知模块（Notification）**
- 站内通知：列表、未读数、标记已读/全部已读、历史记录
- 通知事件：分享/权限变更、评论通知/回复、@提及、任务分配/完成、文档编辑
- 通知分类与过滤：按类型/已读状态/时间范围
- 通知设置：按类型订阅、免打扰
- WebSocket 推送（可降级为轮询）
- **通知必须落库**：WS 仅用于实时展示

8) **系统管理模块（Admin）**
- 用户列表管理与检索
- 用户权限调整（系统角色/状态）
- 用户行为分析（审计统计）
- 用户满意度调查（列表/统计）

9) **通讯模块（Communication）**
- 内置聊天（文档内消息）
- 视频会议集成（会议链接/状态）
- 屏幕共享（开始/结束状态广播）
- 文件共享（上传/下载/历史记录）

10) **审计与日志模块（AuditLog，横切）**
- 记录关键操作：登录、文档 CRUD、ACL 变更、评论/提及、任务等
- 供 Owner/Admin 查询（按文档维度）

## 2. 系统架构设计

### 2.1 架构原则（P0）

- **单体优先**：P0 以单体应用实现 REST + WS，降低协作与部署复杂度
- **强一致数据走 REST**：文档/权限/评论/通知/审计全部落库
- **弱一致状态走 WS**：presence、实时通知推送允许短暂不一致但最终收敛
- **权限强校验**：任何入口（列表/搜索/直链）必须 ACL 过滤与鉴权，避免信息泄露fileciteturn3file0
- **冲突不覆盖**：并发保存必须 409，禁止静默覆盖fileciteturn3file0
- **通知可追溯**：通知先落库再推送，离线可查fileciteturn3file0

---

### 2.2 分层架构（推荐实现）

```text
┌───────────────────────────────┐
│           表现层 UI            │  Web/移动端H5（P0 主要Web）
└───────────────┬───────────────┘
                │ REST / WS
┌───────────────▼───────────────┐
│            接口层 API           │  REST Controller + WS Gateway
│  - 参数校验  - 认证鉴权 - 返回码 │
└───────────────┬───────────────┘
                │ 调用
┌───────────────▼───────────────┐
│            业务层 Domain        │  Service/UseCase
│  DocumentService / ACLService   │
│  CommentService / NotifyService │
│  AuthService / AuditService     │
│  PermissionGuard（统一校验）     │
└───────────────┬───────────────┘
                │ Repo/DAO
┌───────────────▼───────────────┐
│            基础设施层 Infra      │  DB/Redis/对象存储(可选)
│  SQL Repository + Cache + PubSub│
└───────────────────────────────┘
```

**关键点**：PermissionGuard 与 AuditLog 建议通过 **拦截器/中间件**方式接入，减少“每个接口手写校验/日志”的重复。

### 2.4 部署架构（P0 可交付 + 可扩展写法）

**P0 最小部署：**
- 1 个后端服务（REST+WS 同进程）
- 1 个 SQL 数据库（MySQL/PostgreSQL）
- Redis 可选（不影响 P0 主功能）

**扩展部署（当 WS 连接数上升）：**
- 后端多实例水平扩展
- WS 需要 **Sticky Session** 或 **Redis presence + Pub/Sub** 做跨实例在线状态同步

---

### 2.5 数据架构（P0 核心表与关系）

P0 关键实体（概念级）来自需求文档：User、Document、DocMember、Folder、Tag、DocTag、DocumentTemplate、Comment、Task、Notification、NotificationSetting/Pref、UserSatisfaction、ChatMessage、Meeting、SharedFile、AuditLogfileciteturn3file0

推荐关系：
- User 1..N Document（creator/owner）
- Document 1..N DocMember（ACL）
- Document 1..N Comment
- User 1..N Notification
- Document 1..N AuditLog（按 doc_id 查）

**权限过滤关键查询形态：**
- 列表：`docs JOIN doc_members ON ... WHERE doc_members.user_id = ?`
- 搜索：先在 SQL 层完成 ACL 过滤，再做关键字匹配（避免泄露无权限文档）

---

### 2.6 安全与权限架构（P0）

- 认证：JWT/Session（二选一）
- 授权：系统角色（Admin/User） + 文档 ACL（Owner/Editor/Viewer）fileciteturn3file0
- 硬规则：
  1) 仅 Owner/Admin 可改 ACL  
  2) 至少 1 个 Owner，禁止删除最后 Owner  
  3) 任何接口必须服务端校验，不信任前端

---

### 2.7 实时架构（WS）

- **presence**：
  - 客户端打开文档后发送 `presence.join(doc_id)`
  - 服务器校验 Viewer+ 后加入在线集合并广播列表
  - 断线：心跳超时（例如 30s）自动移除并广播离开fileciteturn3file0

- **doc.edit / cursor.update**：
  - 客户端编辑时发送 `doc.edit`（事件广播，不落库）
  - 客户端光标移动时发送 `cursor.update`，服务端广播当前光标列表

- **notification.push**：
  - 写通知落库成功后，若接收者在线则 WS 推送
  - WS 推送失败不影响主链路（通知仍可在通知中心查询）

- **chat.message / file.shared / meeting.start|end / screen.share.start|stop**：
  - 文档内聊天、文件共享、会议状态与屏幕共享通过 WS 广播
  - 仅用于实时 UI 更新，强一致仍以 REST/落库为准

## 3. 核心机制设计（P0）

### 3.1 PermissionGuard（统一权限校验）

输入：user_id、doc_id、min_role（Viewer/Editor/Owner）  
输出：通过/拒绝（403）+ 返回用户在该文档的 role

实现建议：
- 定义 role 等级：Owner(3) > Editor(2) > Viewer(1)
- 查询 DocMember 记录（或 owner_id 冗余字段）
- 若 role < min_role → 拒绝
- ACL 管理：必须 Owner/Admin
- Owner 唯一性：在变更前统计 Owner 数，若将导致 0 Owner → 拒绝

---

### 3.2 并发保存冲突（乐观锁）

- Document.version：每次保存成功 version+1
- 保存请求必须带 `base_version`
- 条件更新：
  - 成功：返回 new_version
  - 失败：返回 **409 Conflict** + current_version + updated_at
- 目标：**绝不静默覆盖**fileciteturn3file0

---

### 3.3 评论锚点（块/段落级）

P0 锚点策略：
- block_id（推荐：按段落 hash 或渲染后生成的稳定块ID）
- 或 paragraph_index（段落序号）
- 不做字符级范围漂移（P2 才考虑）

---

### 3.4 通知落库 + 推送

- 同步：事务内写 Notification 记录（确保可追溯）
- 异步：事务后尝试 WS 推送（在线则即时到达）
- 未读数：基于 Notification.is_read 统计
- 分类过滤：支持按类型/已读状态/时间范围检索
- 通知设置：按类型订阅 + 免打扰（关闭则不落库/不推送）

---

### 3.5 审计日志（横切）

- 记录：actor_id、action、target_type/target_id、result、ip、meta
- 关键动作（P0）：登录、创建/编辑/删除文档、重命名、ACL 变更、评论/提及、任务
- 查询：Owner/Admin 可按 doc_id 分页查看

---

## 4. 功能主要流程（主流程 + 关键异常）

> 以下流程以“文字版时序图/流程图”描述，便于直接转为接口与测试用例。

### 4.1 注册/登录/找回重置（Auth）

**登录主流程（示意）：**
1. Client → `POST /auth/login`（account, password）
2. Backend：校验密码 → 签发 token/session
3. Backend：写 AuditLog（login_success）
4. Backend → Client：返回 token + user_profile

**异常：**
- 密码错误：401 + 写 login_fail（可选限流）
- 账号冻结：403

---

### 4.2 创建文档（Document + ACL + Audit）

```text
Client -> POST /docs (title, content, folder_id?, template_id?, content_format?, tag_ids?)
Backend -> Permission: 已登录
Backend -> DB: insert Document(version=1, owner=me)
Backend -> DB: upsert DocMember(me, Owner)
Backend -> DB: insert AuditLog(doc.create)
Backend -> Client: doc_id + 初始 version
```

**异常：**
- 未登录：401
- 参数非法：400
- DB 失败：500（不产生半成品或回滚）

---

### 4.3 打开文档 + 加入协作会话（REST + WS）

**打开（REST）：**
1. Client → `GET /docs/{id}`
2. Backend → PermissionGuard：Viewer+ 校验
3. Backend → Client：返回 content + version + my_role

**加入会话（WS）：**
1. Client 建立 WS → 发送 `presence.join(doc_id)`
2. WS Server → PermissionGuard：Viewer+ 校验
3. WS Server：加入在线集合 & 广播在线列表
4. Clients：更新 UI 在线成员列表

**异常/降级：**
- WS 失败：仅缺失 presence，不影响编辑/评论/通知中心查询

---

### 4.4 编辑保存（含自动保存）+ 冲突处理（409）

**保存主流程：**
1. Client 编辑 → `PUT /docs/{id}`（content, base_version, content_format?）
2. Backend → PermissionGuard：Editor+ 校验
3. Backend：条件更新 `WHERE version=base_version` 成功则 version+1
4. Backend：写 AuditLog(doc.save)
5. Backend → Client：返回 new_version

**冲突（409）分支：**
- 条件更新失败 → Backend 返回 409 + current_version + updated_at
- Client 提示“已被他人更新，请刷新后再编辑”
- P0 要求：**不覆盖**，直到用户刷新或重新打开

---

### 4.5 分享/修改权限（ACL）+ 通知 + 审计

**主流程：**
1. Owner → `PUT /docs/{id}/members`（target_user, role）
2. Backend：PermissionGuard（Owner/Admin）
3. Backend：校验 Owner 唯一性（防止 0 Owner）
4. Backend：upsert DocMember(target_user, role)
5. Backend：写 Notification（share/role_change）给 target_user
6. Backend：写 AuditLog(acl.update)
7. 若 target_user 在线：WS 推送 `notification.push`

**异常：**
- 非 Owner/Admin：403
- 目标用户不存在：404/400
- 移除最后 Owner：400/409（按实现），并拒绝变更

---

### 4.6 评论/回复/@提及（Comment + Mention + Notification）

**创建评论：**
1. Client → `POST /docs/{id}/comments`（anchor, content, mentions[]）
2. Backend：PermissionGuard（Viewer+，P0 默认允许评论）
3. Backend：写 Comment
4. Backend：对 mentions[] 写 Notification（mention）
5. Backend：写 AuditLog(comment.create)（可选但建议）
6. WS 推送给被@者（在线）

**回复：**
- 同上，增加 thread_id/parent_id，并通知主评论作者

---

### 4.7 通知中心（Notification）

**拉取：**
1. Client → `GET /notifications?page=...`
2. Backend：按 user_id 返回列表 + 未读数（或单独接口）

**已读：**
1. Client → `POST /notifications/read`（id 或 all=true）
2. Backend：更新 is_read/read_at
3. Client：未读数减少

**异常：**
- WS 不可用：仍可通过 REST 获取通知（可追溯）

---

### 4.8 审计日志查询（AuditLog）

1. Owner/Admin → `GET /docs/{id}/audit?page=...`
2. Backend：PermissionGuard（Owner/Admin）
3. Backend：按 doc_id 分页返回审计日志

## 5. 接口与事件清单（P0 摘要）

### 5.1 REST API（摘要）

- Auth：`POST /auth/register` `POST /auth/login` `POST /auth/forgot` `POST /auth/reset`
- User：`GET /users/me` `PUT /users/me`
- Docs：`POST /docs` `GET /docs/:id` `PUT /docs/:id` `PUT /docs/:id/autosave` `PUT /docs/:id/title` `DELETE /docs/:id`
- Folder：`GET /folders` `POST /folders` `PUT /folders/:id` `DELETE /folders/:id`
- ACL：`GET /docs/:id/members` `PUT /docs/:id/members`
- Search/List：`GET /docs?folderId=...&tagId=...&sortBy=...` `GET /search?q=...&authorId=...&from=...&to=...&tagId=...&sortBy=...`
- Template：`POST /templates` `GET /templates` `GET /templates/:id` `PUT /templates/:id` `DELETE /templates/:id`
- Tag：`GET /tags` `POST /tags` `PUT /tags/:id` `DELETE /tags/:id` `GET /docs/:id/tags` `PUT /docs/:id/tags`
- Task：`POST /docs/:id/tasks` `GET /docs/:id/tasks` `PUT /tasks/:id` `GET /tasks/assigned`
- Comment：`POST /docs/:id/comments` `POST /comments/:id/replies`

## 7. 演示脚本（P0 亮点闭环）

1. A 注册登录 → 创建文档 → 分享给 B（Viewer）
2. B 打开文档：看到 A 在线（presence）
3. B 评论并 @A：A 收到通知并跳转到评论位置
4. A 将 B 升级为 Editor
5. A 创建任务并指派给 B：B 收到任务通知
6. B 完成任务：A/B 收到完成通知
7. A、B 并发编辑并保存：后保存者触发 409 冲突提示（不覆盖）
8. A 查看审计日志：看到 ACL 变更、保存、评论、任务等记录
9. A 在文档内发送聊天消息：B 实时收到 `chat.message`
10. A 发起会议：B 看到 `meeting.start` 并进入会议链接
11. A 开始屏幕共享并上传文件：B 收到 `screen.share.start` 与 `file.shared`
