# 系统管理模块测试方案（Postman）

## 1. 测试范围

- 用户列表管理（检索/筛选/分页）
- 用户权限调整（系统角色/状态）
- 用户行为分析（审计统计）
- 用户满意度调查（提交/统计）

## 2. 环境准备

1) 应用已启动（端口 8080）。
2) 数据库包含 `t_user_satisfaction` 表（可通过 `db/schema.mysql.sql` 或 `ddl-auto=update`）。
3) 准备 Admin 账号：
   - 方案 A：在 `application.properties` 开启 `docflow.bootstrap.enabled=true`，重启后使用配置的 admin 账号登录。
   - 方案 B：用已有 Admin 账号登录（若已有）。

## 3. Postman 环境变量

```
baseUrl = http://localhost:8080
wsUrl = ws://localhost:8080/ws
tokenAdmin = <Admin 登录 token>
tokenA = <A 的登录 token>
tokenB = <B 的登录 token>
userIdA = <A 的 userId>
userIdB = <B 的 userId>
userId = <目标用户 ID，建议填 B 的 userId>
docId = <A 创建的文档 ID>
taskId = <任务 ID>
commentId = <评论 ID>
meetingId = <会议 ID>
fileId = <文件 ID>
```

## 4. 初始化步骤（获取 token 与关键 ID）

说明：系统管理模块测试主要依赖 `tokenAdmin` 与 `userId`。若只测管理功能，可只完成 4.1~4.3。

### 4.1 登录 A（usera）

如账号未注册，先注册：
```
POST {{baseUrl}}/auth/register
Content-Type: application/json

{"email":"usera@example.com","password":"usera123","nickname":"UserA"}
```

登录获取 `tokenA` 与 `userIdA`：
```
POST {{baseUrl}}/auth/login
Content-Type: application/json

{"account":"usera@example.com","password":"usera123"}
```

Tests（自动写入变量）：
```javascript
const data = pm.response.json();
pm.environment.set("tokenA", data.token);
pm.environment.set("userIdA", data.user.id);
```

### 4.2 登录 B（userb）

如账号未注册，先注册：
```
POST {{baseUrl}}/auth/register
Content-Type: application/json

{"email":"userb@example.com","password":"userb123","nickname":"UserB"}
```

登录获取 `tokenB` 与 `userIdB`：
```
POST {{baseUrl}}/auth/login
Content-Type: application/json

{"account":"userb@example.com","password":"userb123"}
```

Tests（自动写入变量）：
```javascript
const data = pm.response.json();

```

### 4.3 登录 Admin（获取 tokenAdmin）

若使用 bootstrap 的默认配置：
```
POST {{baseUrl}}/auth/login
Content-Type: application/json

{"account":"admin@example.com","password":"admin123"}
```

Tests（自动写入变量）：
```javascript

```

### 4.4 创建文档并共享给 B（获取 docId，可选）

创建文档（A）：
```
POST {{baseUrl}}/docs
Authorization: Bearer {{tokenA}}
Content-Type: application/json

{"title":"Admin Test Doc","content":"init","format":"RICH_TEXT"}
```

Tests（自动写入变量）：
```javascript
const data = pm.response.json();
pm.environment.set("docId", data.id);
```

共享给 B（便于产生行为日志）：
```
PUT {{baseUrl}}/docs/{{docId}}/members
Authorization: Bearer {{tokenA}}
Content-Type: application/json

{"userId": {{userIdB}}, "role":"EDITOR", "remove": false}
```

## 5. 管理员接口测试

### TC-01 用户列表（分页）

请求：
```
GET {{baseUrl}}/admin/users?page=0&size=20
Authorization: Bearer {{tokenAdmin}}
```

期望：
- 200 OK
- 返回分页结构（items/page/size/totalItems/totalPages）

### TC-02 用户列表（关键字检索）

请求：
```
GET {{baseUrl}}/admin/users?q=example
Authorization: Bearer {{tokenAdmin}}
```

期望：
- 返回 email/phone/nickname 匹配的用户

### TC-03 用户列表（角色/状态筛选）

请求：
```
GET {{baseUrl}}/admin/users?role=ADMIN&status=ACTIVE
Authorization: Bearer {{tokenAdmin}}
```

期望：
- 仅返回符合角色与状态的用户

### TC-04 更新系统角色

请求：
```
PUT {{baseUrl}}/admin/users/{{userId}}/role
Authorization: Bearer {{tokenAdmin}}
Content-Type: application/json

{"role":"ADMIN"}
```

期望：
- 目标用户角色变更
- 审计日志新增 `system_role_update`

### TC-05 更新用户状态

请求：
```
PUT {{baseUrl}}/admin/users/{{userId}}/status
Authorization: Bearer {{tokenAdmin}}
Content-Type: application/json

{"status":"FROZEN"}
```

期望：
- 用户状态变为 FROZEN
- 审计日志新增 `user_status_update`

### TC-06 用户行为分析

请求：
```
GET {{baseUrl}}/admin/users/{{userId}}/behavior
Authorization: Bearer {{tokenAdmin}}
```

期望：
- 返回 totalActions、lastActiveAt、actions 统计

### TC-07 用户审计日志（可选）

请求：
```
GET {{baseUrl}}/admin/users/{{userId}}/audit?page=0&size=20
Authorization: Bearer {{tokenAdmin}}
```

期望：
- 返回该用户的审计记录列表

## 6. 满意度调查

### TC-08 用户提交满意度

请求：
```
POST {{baseUrl}}/surveys
Authorization: Bearer {{tokenB}}
Content-Type: application/json

{"rating":4,"comment":"功能完整，体验不错"}
```

期望：
- 返回提交记录（id、rating、createdAt）

### TC-09 管理员查看满意度列表

请求：
```
GET {{baseUrl}}/admin/surveys?page=0&size=20
Authorization: Bearer {{tokenAdmin}}
```

期望：
- 返回列表与分页信息

### TC-10 满意度统计

请求：
```
GET {{baseUrl}}/admin/surveys/stats
Authorization: Bearer {{tokenAdmin}}
```

期望：
- 返回 averageRating 与 rating 分布

## 7. 权限校验（必须）

### TC-11 非管理员访问 /admin

请求：
```
GET {{baseUrl}}/admin/users
Authorization: Bearer {{tokenB}}
```

期望：
- 403 Forbidden

## 8. 常见问题排查

- 401 Unauthorized：检查 `Authorization` 是否正确。
- 403 Forbidden：确认账号是 ADMIN。
- 数据为空：确认已存在用户或已提交满意度。
