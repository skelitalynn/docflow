# 通知与通讯模块测试方案（Postman）

## 1. 测试范围

- 通知系统：实时通知（编辑/评论/任务等）、分类与过滤、通知设置、历史记录
- 通讯模块：聊天、视频会议集成、屏幕共享、文件共享
- WebSocket 推送：`notification.push`、`chat.message`、`meeting.start/end`、`screen.share.start/stop`、`file.shared`

## 2. 环境准备

1) 应用已启动（端口默认为 8080）。
2) 数据库已包含新增表：`t_notification_pref`、`t_notification_setting`、`t_chat_message`、`t_meeting`、`t_shared_file`。
   - 若使用 `db/schema.mysql.sql` 初始化，请重新执行或做增量迁移。
   - 若使用 `spring.jpa.hibernate.ddl-auto=update`，启动后会自动建表。
3) 准备两个账号 A/B（用于权限与协作验证）。

## 3. Postman 环境变量

```
baseUrl = http://localhost:8080
wsUrl = ws://localhost:8080/ws
tokenA = <A 的登录 token>
tokenB = <B 的登录 token>
userIdA = <A 的 userId>
userIdB = <B 的 userId>
docId = <A 创建的文档 ID>
taskId = <任务 ID>
commentId = <评论 ID>
meetingId = <会议 ID>
fileId = <文件 ID>
```

## 4. 初始化步骤（获取 token 与关键 ID）

说明：若只想验证通知/通讯功能，请按 4.1~4.7 完成变量初始化。

### 4.1 登录 A（usera）

如账号未注册，先注册：
```
POST {{baseUrl}}/auth/register
Content-Type: application/json

{"email":"usera@example.com","password":"usera123","nickname":"UserA"}
```

登录获取 `tokenA` 与 `userIdA`：
```
POST {{baseUrl}}/auth/login
Content-Type: application/json

{"account":"usera@example.com","password":"usera123"}
```

Tests（自动写入变量）：
```javascript
const data = pm.response.json();
pm.environment.set("tokenA", data.token);
pm.environment.set("userIdA", data.user.id);
```

### 4.2 登录 B（userb）

如账号未注册，先注册：
```
POST {{baseUrl}}/auth/register
Content-Type: application/json

{"email":"userb@example.com","password":"userb123","nickname":"UserB"}
```

登录获取 `tokenB` 与 `userIdB`：
```
POST {{baseUrl}}/auth/login
Content-Type: application/json

{"account":"userb@example.com","password":"userb123"}
```

Tests（自动写入变量）：
```javascript
const data = pm.response.json();
pm.environment.set("tokenB", data.token);
pm.environment.set("userIdB", data.user.id);
```

### 4.3 创建文档并共享给 B（获取 docId）

创建文档（A）：
```
POST {{baseUrl}}/docs
Authorization: Bearer {{tokenA}}
Content-Type: application/json

{"title":"Notify/Comms Test Doc","content":"init","format":"RICH_TEXT"}
```

从响应取 `id` → 填入 `docId`。

Tests（自动写入变量）：
```javascript
const data = pm.response.json();
pm.environment.set("docId", data.id);
```

共享给 B（便于后续任务/评论/会议/文件测试）：
```
PUT {{baseUrl}}/docs/{{docId}}/members
Authorization: Bearer {{tokenA}}
Content-Type: application/json

{"userId": {{userIdB}}, "role":"EDITOR", "remove": false}
```

### 4.4 创建任务（获取 taskId）

```
POST {{baseUrl}}/docs/{{docId}}/tasks
Authorization: Bearer {{tokenA}}
Content-Type: application/json
```

### 4.5 创建评论（获取 commentId）

```
POST {{baseUrl}}/docs/{{docId}}/comments
Authorization: Bearer {{tokenB}}
Content-Type: application/json

{"content":"init comment","blockId":"p-1","paragraphIndex":1,"mentions":[{{userIdA}}]}
```

从响应取 `id` → 填入 `commentId`。

Tests（自动写入变量）：


### 4.6 发起会议（获取 meetingId）

```
POST {{baseUrl}}/docs/{{docId}}/meetings
Authorization: Bearer {{tokenA}}
Content-Type: application/json

{"title":"Notify Meeting","provider":"custom","joinUrl":""}
```

从响应取 `id` → 填入 `meetingId`。

Tests（自动写入变量）：


### 4.7 上传文件（获取 fileId）

```
POST {{baseUrl}}/docs/{{docId}}/files
Authorization: Bearer {{tokenA}}
Content-Type: multipart/form-data
file=@/path/to/demo.pdf
```

从响应取 `id` → 填入 `fileId`。

Tests（自动写入变量）：

### 4.8 建立 WS 连接（可选，但用于验证实时推送）

- A：连接 `{{wsUrl}}?token={{tokenA}}`  
- B：连接 `{{wsUrl}}?token={{tokenB}}`

连接后发送加入消息：
```json
{"type":"presence.join","data":{"docId":{{docId}}}}
```

## 5. 通知模块测试

### TC-01 分享/权限变更通知

请求：
```
PUT {{baseUrl}}/docs/{{docId}}/members
Authorization: Bearer {{tokenA}}
Content-Type: application/json

{"userId": {{userIdB}}, "role":"EDITOR", "remove": false}
```

期望：
- B 的 `/notifications` 中出现 `SHARE` 通知
- WS 若在线，B 收到 `notification.push`

### TC-02 新评论通知

请求：
```
POST {{baseUrl}}/docs/{{docId}}/comments
Authorization: Bearer {{tokenB}}
Content-Type: application/json

{"content":"test comment","blockId":"p-1","paragraphIndex":1,"mentions":[]}
```

期望：
- 文档 Owner 收到 `COMMENT` 通知
- 通知落库 + WS 推送（若在线）

请求：
```

Authorization: Bearer {{tokenB}}
Content-Type: application/json

{"content":"reply","mentions":[]}
```

期望：
- 主评论作者收到 `COMMENT_REPLY` 通知

```
Authorization: Bearer {{tokenB}}
Content-Type: application/json
```

### TC-05 任务通知（分配）

### TC-06 任务通知（完成）

请求：

请求：

```
Content-Type: application/json

```

```

Authorization: Bearer {{tokenA}}
```

期望：

### TC-10 通知设置（全局免打扰）

请求：
```

Content-Type: application/json

{"muteAll": true}
```

- 新通知不再落库/推送
- `GET /notifications/settings` 返回 `muteAll=true`

请求：
```

```

请求：
```

```

期望：

## 7. 常见问题排查

- 401 Unauthorized：检查 `Authorization: Bearer {{token}}` 是否正确。
- 403 No document access：确认调用者在文档 ACL 中至少为 Viewer/Editor。
- WS 收不到推送：确认已 `presence.join` 进入文档并保持连接。
- 通知不落库：检查 `/notifications/settings` 是否开启免打扰或关闭了对应类型。
